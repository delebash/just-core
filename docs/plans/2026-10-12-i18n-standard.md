# Every app and the kit on vue-i18n — the plan (2026-10-12)

> **For agentic workers:** executed inline by the session that wrote it (the user retired the
> delegated executor, 2026-07-20). Steps use checkbox (`- [ ]`) syntax; each task is ticked here
> with its commits when it lands. **Nothing in this plan runs before the user's go on it**, and the
> pieces marked NOT STANDARD and the decisions D1–D6 each wait for the user's word by name.

**Goal:** every family app (JustWrite, JustVoice, docgen, the template) and the kit render all
their words through vue-i18n and nothing else, so docgen can translate every catalog and a new app
starts that way from the template.

**The ruling** (this repo's `docs/dev/TASKS.md`, "Every app and the kit on vue-i18n"): the user,
2026-10-12 — *"all apps should use the standard i18n including kit, everything should be standard
no strange worki arounds, what needs to be done"*, then *"your rec go"* on the answer recorded
there.

**Architecture:** the kit keeps its words in its own vue-i18n catalog
(`ui/src/i18n/locales/<code>.json`, every key under `kit.`) and exports it as `kitMessages()`. Each app
creates the one vue-i18n instance in its i18n boot file from the kit's catalog and its own, its own
merged last, so an app can reword a kit key in its own file. Kit components translate with
`useI18n()`; the kit's non-component code translates through the instance the app passes to
`installLlmUi(app, { i18n })`. Quasar's built-in words follow the app's language through Quasar's
language packs; dates and numbers format through vue-i18n. docgen translates every catalog — the
kit's and each app's — and the user reviews there. The kit's other text doors go: the labels feed,
the label parts of `configureDialog`, `catalogCopy` and the text in `quickSetupCopy`, and `setUiLocale`.

**Tech stack:** vue-i18n 11.4 in Composition mode (12 is not released; `useI18n()` and `$t` carry
over unchanged), Quasar 2.35 + @quasar/app-vite, @intlify/eslint-plugin-vue-i18n, vue-i18n-extract,
pseudo-localization, @vue/test-utils, docgen.

**Spec:** the July research and its seven decisions —
`../../justwrite-app/docs/plans/2026-07-26-i18n-single-source-research.md` (decisions as blessed:
`../../justwrite-app/docs/plans/archive/2026-07-26-i18n-phase1-coverage-plan.md`, its header) — and
the ruling above. The measurements this plan rests on: JustWrite's `docs/dev/RESEARCH.md`
"Translation: what still shows in English" and this repo's `docs/dev/RESEARCH.md` §8.

## Global constraints

- Plain JavaScript, `.js` only; Biome clean on every touched file; never reformat unrelated code.
- One mechanism: every user-facing word is a vue-i18n message. No label stores, copy objects or
  locale setters beside it.
- English is the source: each catalog's `en.json` is the world for its words; `vue-i18n-extract`
  MISSING stays 0 in every app and the kit — over the English catalogs: the reports read `en.json`
  only, other languages fill through docgen and show English until then (ruled 2026-10-13).
- Kit keys live under `kit.` (D1); an app's file may set a `kit.` key only to reword it.
- Nothing translated by hand from here on except what already exists: the Spanish the apps ship
  today moves with its keys; everything new waits for docgen (Task 6).
- Never touch the user's live `:1420` / `:17495`; isolated servers on copies of `data/`.
- Nothing in JustVoice's folders without D2.
- User docs change in the same commit as the behaviour; the family guard before every commit.

// src/i18n/kitI18n.test.js — @vitest-environment jsdom
import { mount } from "@vue/test-utils";
import { createI18n } from "vue-i18n";
import { DownloadBar } from "@delebash/llm-ui";
import { kitMessages } from "@delebash/llm-ui/i18n/index.js";
const KIT = kitMessages();

const make = (appMessages = {}) => {
  const i18n = createI18n({ legacy: false, locale: "en", fallbackLocale: "en", messages: kitMessages() });
  for (const [code, msgs] of Object.entries(appMessages)) i18n.global.mergeLocaleMessage(code, msgs);
  return i18n;
};

it("a kit component speaks the app's language and switches live", async () => {
  const i18n = make();
  const task = { state: "error", retry() {}, dismiss() {} }; // a failed download: Retry + Dismiss
  const w = mount(DownloadBar, { props: { task }, global: { plugins: [i18n] } });
  expect(w.text()).toContain(KIT.en.kit.downloadBar.retry);
  i18n.global.locale.value = "es";
  await w.vm.$nextTick();
  expect(w.text()).toContain(KIT.es.kit.downloadBar.retry);
});
it("an app's own word for a kit key wins", () => {
  const i18n = make({ en: { kit: { downloadBar: { retry: "Try again" } } } });
  const w = mount(DownloadBar, { props: { task: { state: "error", retry() {} } }, global: { plugins: [i18n] } });
  expect(w.text()).toContain("Try again");
});
it("a language the kit lacks falls back to English, never a raw key", () => {
  const i18n = make();
  i18n.global.locale.value = "fr";
  const w = mount(DownloadBar, { props: { task: { state: "error", retry() {} } }, global: { plugins: [i18n] } });
  expect(w.text()).toContain(KIT.en.kit.downloadBar.retry);
  expect(w.text()).not.toContain("kit.downloadBar");
});

- [x] **Step 3: Quasar's words follow the language** (step A).

```js
// ui/src/quasar/lang.js — Quasar's language packs, as quasar.dev/options/quasar-language-packs
// loads them dynamically, re-set whenever the app's language changes. `packs` is the app's own
// import.meta.glob of quasar/lang/*.js (the path is relative to the app, as the doc's boot file is).
import { Lang } from "quasar";
import { watch } from "vue";
export function followQuasarLang(i18n, packs) {
  const byIso = Object.fromEntries(Object.keys(packs).map((p) => [p.match(/([^/]+)\.js$/)[1], p]));
  const apply = async (code) => {
    const iso = Lang.getClosestIsoName(code, Object.keys(byIso));
    if (iso) Lang.set((await packs[byIso[iso]]()).default);
  };
  watch(i18n.global.locale, apply, { immediate: true });
}
```
